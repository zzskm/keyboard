## 커버 및 plate L/R 개선 계획

상태는 설계 후보 검토 전이다. 치수와 합격 기준은 1차 비교용이며, 실측과 시험 결과를 기록한 뒤 채택한다.

### 0. 기준 리비전과 현행 형상 확인

- 병합 상태가 정리된 기준 커밋을 확정한다. 생성기, CAD, 치수 CSV, 조립 검토 모델, 쿠폰을 같은 리비전으로 맞춘다. 현행·후보 쿠폰은 [생성기](../tools/build_seam_v5.py)의 공통 치수에서 생성하고, [내보낸 치수 CSV](../model/parameters_seam_v5.csv)로 대조한다.
- 앞 이음, 중앙 앞 mount, 인접 스위치, 커버를 같은 단면에 표시한다. 나사머리와 커버, 너트·나사 끝과 mount, 반턱 접촉면을 확인한다. 검토 중 언급된 빨간 띠·원은 원본 도면 또는 캡처 확보 후 해당 바디와 대조한다. 실제 간섭이 확인되면 후보 설계 전에 해결한다.
- 현행 L/R 출력품을 각각 기준 평판에 올리고, 돌출 피처를 피해 동일 높이 블록 3개로 받친다. 체결 전 이음의 앞·중앙·뒤 높이와 최대 편차를 기록해 본체 휨과 이음 형상의 영향을 구분한다.

### 1. 커버 창 단순화 및 높이 검토

1. 창 단순화는 main에 채택했다(2026-11-10, [결정 이력](design.md#결정-이력)): 키 블록 실루엣 윤곽 2개, 셀 20.35, 외곽 살 1.1, 윗면 Z 19 유지. 높이(아래 2–4)는 `codex/46es-cover-plate-trial` 브랜치에서 시험한다. 저상화하면 창 윤곽과 자석·보스 주변 잔여 두께를 같은 방식으로 다시 확인한다.
2. PSD60 지지대 상면을 기준으로 앞·뒤 테두리 높이를 잰다. r2 조립품의 같은 위치에서 돌출을 재고, 실제 키캡 스커트 높이를 쉴 때와 끝까지 눌렀을 때 각각 기록한다. r2 커버 본체는 공칭 7 mm, v5 현행은 6 mm다. v5의 약 5 mm 돌출은 CAD와 대략 실측 테두리의 차이며, r2 현물 기록은 최소 3 mm다.
3. 현행 Z19와 첫 후보 Z18.5를 비교한다. Z18.5에서 본체 5.5 mm, 테두리 위 약 4.5 mm, 참고 키캡의 정지 상태 스커트 덮임 약 1.2 mm다. 추가 저상화가 필요하면 Z18을 비교한다. 이때 각각 5.0, 약 4.0, 약 0.7 mm다.
4. 참고 키캡의 정지·4 mm 눌림 상태에서 창과의 최소 간격 1.0 mm, 다리 자석 포켓 위 살 1.3 mm 이상을 확인한다. 보스와 립의 착좌, 창 가장자리의 연속된 살, 앞 이음 나사머리 간격을 CAD에서 확인한 뒤 실제 키캡의 스트로크·풀러 접근과 커버 흡착·들뜸·휨을 시험한다. 현행과 후보의 정면·측면 단면에 돌출량을 표시한다.

### 2. plate L/R 앞 이음 및 하중 경로

1. SO3·SO6 M3 홀이 어느 plate에 속하는지 CAD에서 확인하고, R 안쪽 열 아래 직접 닿는 mount 받침을 표시한다. R에 직접 체결되는 M3가 우측의 SO4·SO5 두 개라면, 받침이 닿는 곳은 mount로 하중을 전달하고 그 사이의 하중은 R plate 굽힘을 거쳐 앞 반턱과 중앙·뒤 spine으로 분담된다. 반턱의 접촉면은 눌림을 받고 M2는 반턱을 조여 들뜸을 억제한다. Rear shim은 접촉 여부를 별도로 확인한다.
2. 앞 이음은 위에서 끼우는 직선 반턱 **2.4 mm**, 위치결정 턱 편측 **0.15 mm**, 저두 **M2×5 한 개**로 시작한다. 스위치와 잔여 벽 두께를 고려해 턱을 나사에서 가능한 멀리 두고, 턱의 접촉면으로 벌어짐과 평면 내 회전을 제한한다. 하부 spine의 M2 4개, 배선 홈, 받침은 비교 기간에 현행 구성을 사용한다.
3. R의 측면 삽입식 육각 너트 포켓은 실제 M2 너트 대변 4.0 mm·두께 1.6 mm를 출발값으로 잡는다. 육각 면으로 회전을 막고 입구 턱으로 빠짐을 제한하며, 반대쪽 구멍으로 밀어내 교체할 수 있게 한다. 너트 삽입 경로·mount 회피 공간·포켓 벽과 분말 제거를 단면에서 확인한다. 벽 두께나 유지력 기준을 충족하기 어려우면 열압입 인서트를 비교한다.
4. 현행 도브테일과 직선 반턱을 동일한 MJF 재료·출력 방향·하드웨어·체결 조건으로 시험한다. 위치결정 턱 여유는 0.15 mm와 한 단계 넓힌 값을 비교하고, 너트 포켓 여유는 독립적으로 시험한다. 본체에서는 앞 이음만 체결한 상태, spine을 붙인 상태, 케이스 장착 상태 순으로 앞·중앙·뒤 단차를 기록한다.

| 시험 | 1차 합격 기준 |
|---|---|
| 쿠폰 삽입 | 나사 없이 손으로 5회 중 5회 완전 착좌 |
| 너트 유지 | 나사를 뺀 채 뒤집어 가볍게 흔드는 10회 동안 이탈 0회, 위에서 체결할 때 공회전 0회 |
| 쿠폰 단차·내구 | 체결 후 단차 0.20 mm 이하. 10회 탈착 후 단차와 면내 유격 증가 각각 0.10 mm 이하, 포켓 균열 없음 |
| R 안쪽 열 하중 | 케이스 완전 조립 상태에서 앞·중앙·뒤의 이음에 가장 가까운 R쪽 키 위치를 각각 5 N으로 누른다. L/R 상대 변위 0.20 mm 이하, 하중 제거 후 잔류 변위 0.10 mm 이하, 현행 대비 상대 변위 증가와 반복 소음 없음 |
| 배선·정비 | 배선이 spine 홈에 눌리지 않고 상부 M3 6개를 풀어 plate·스위치·배선 모듈을 통째로 들어낼 수 있음 |

앞쪽에서 회전이나 들뜸이 남으면 턱의 접촉 방향과 나사와의 거리를 먼저 조정한다. 그래도 기준을 넘으면 M2 두 개를 검토한다. 중앙·뒤쪽에만 움직임이 남으면 spine 접촉과 Rear shim을 별도로 검토한다. 5 N은 현행과 후보를 비교하기 위한 시험 하중이다.

### 3. 채택 및 반영

첫 산출물은 기준 리비전이 표시된 현행 앞 이음 단면과 R 안쪽 하중 경로, 커버 현행·후보 단면이다. 채택 치수와 시험 결과를 기록한 뒤 생성기, 영향받는 검토·제작 출력, 쿠폰, 검증 결과와 조립 가이드를 함께 갱신한다. CAD 검사와 실물 합격은 각각 기록하고, 본 출력 여부는 시험 결과를 바탕으로 결정한다.

## 재생성 (저장소 루트)

SolidCraft CLI와 `46es/requirements.txt`의 Python 패키지(`pip install -r 46es/requirements.txt`)가 설치된 Windows 환경에서 실행한다. CLI 경로는 환경변수 `SOLIDCRAFT_CLI`, 없으면 기본 설치 경로 `C:/Program Files/SolidCraft/solidcraft-cli.exe`다(`tools/common.py`). 가이드는 `--cli`로도 지정할 수 있다. 콘솔 출력은 스크립트가 UTF-8로 바꾸므로 `PYTHONUTF8`을 따로 설정하지 않아도 된다.

생성 CAD `46es/model/*.sc` 3개(현행·조립 검토·시험편)는 2026-11-10부터 Git LFS에 둔다(`46es/.gitattributes`). 재생성마다 약 18 MB씩 저장소에 쌓이던 것을 막는다. 그 전 커밋의 `.sc`는 일반 blob 그대로다(이력 재작성 없음). clone에는 [Git LFS](https://git-lfs.com)가 필요하고, LFS 없이 받으면 `.sc`가 포인터 파일이라 `check_repository.py`가 `git lfs install && git lfs pull`을 안내하며 멈춘다. `core.hooksPath .githooks`를 쓰면 `.git/hooks`가 무시되므로 LFS 훅(`pre-push` 등 4개)도 `.githooks/`에 있다. CI는 LFS 객체를 id로 캐시해 처음 보는 CAD만 내려받는다.

이 절이 46es 명령의 유일한 목록이다. 다른 문서는 여기를 가리킨다.

```sh
python 46es/tools/pipeline.py --status                    # 단계마다 ok / 낡음(이유) / 앞 단계 뒤 재실행. SolidCraft 불필요, 수 초
python 46es/tools/pipeline.py --run                       # 낡은 단계만 순서대로 실행(각 단계 직전에 다시 판정)
python 46es/tools/pipeline.py --run --from verify_seam    # 그 단계와 이후 전부
python 46es/tools/pipeline.py --run --only print         # 지정 단계만(지정하면 전부 다시: 내보내기 코드만 고쳤을 때)
```

`pipeline.py`의 단계와 그 단계가 실행하는 명령(따로 실행해도 같다):

```sh
python 46es/tools/build_seam_v5.py                         # seam: 현행 CAD, 시험편 A·C 모델, CSV, 생성 기록
python 46es/tools/export_print_v5.py                       # print: 주문 1·2(--order order1|order2로 하나만, --force로 전부 다시)
python -B 46es/inspection/scripts/verify_seam_v5.py        # verify_seam(--accept: 의도한 설계 변경 뒤 기준 갱신, 아래)
python 46es/tools/build_assembly_reference_v5.py           # assembly
python -B 46es/inspection/scripts/verify_assembly_reference_v5.py   # verify_assembly
python -B 46es/guide/review_guide.py --steps standoff trial module --views reset iso   # review(캡처만, 판정은 사람)
```

파이프라인 밖의 명령:

```sh
python 46es/tools/build_seam_v5.py --mounts           # mount만 바꿀 때: 약 5 s, 도면 단면 비교
python 46es/tools/build_seam_v5.py --ctrl             # 브래킷 B·시험편 A·C만: 약 20 s, 금지 영역·부피 추정 비교
python 46es/tools/build_seam_v5.py --covers           # 커버 3조각만: 약 9 s, 윗면·조각 범위·자석 살, 생산 CAD와 BRep 비교
python 46es/tools/doc_tables.py --write               # 주문 기록이 바뀐 뒤: print_v5/README.md 부품 표의 크기·부피·최소 벽 칸
python 46es/tools/pipeline.py --clean                 # 쓰지 않는 캐시 삭제(아래)
python 46es/tools/build_seam_v5.py --refresh-record   # 형상이 그대로인 생성기 정리 뒤: CAD 유지, 생성 기록만 갱신
python 46es/guide/build_guide.py                      # 로컬 가이드 전체 빌드(guide/out, 옵션은 guide/README.md)
python -B 46es/tools/finish.py                        # 커밋 전 마무리(아래 「CAD 없이 할 수 있는 검사」)
python 46es/guide/publish_guide.py                    # main 병합·push 뒤 가이드 게시(guide/README.md 「게시」)
```

낡음 판정은 커밋된 기록으로 한다. seam은 생성 기록의 입력 지문·출력 해시, print는 주문 기록과 부품 표 `tools/parts_v5.py`·원본 CAD·STL/STEP 해시(낡은 주문만 다시 내보낸다), 두 검증 단계는 기록의 `inputs`(검증 스크립트 자신과 읽은 파일의 지문), assembly는 `assembly_reference_v5.json`의 해시, review는 현재 검토 모델·가이드 spec으로 찍은 `guide/.cache/visual-review/` 캡처가 있는지다. 내보내기 코드(`export_print_v5.py`와 STL 스크립트)는 지문을 남기지 않으므로 고쳤으면 `--only print`로 전부 다시 내보낸다. 생성기 코드만 바뀌어 seam이 낡았으면 `--status`가 `--refresh-record`를 안내한다. 실행한 단계의 벽시계 시간은 `46es/.cache/pipeline-timings.json`에 쌓이고 `--status`에 마지막 시간이 보인다.

캐시는 Git에서 제외된 `46es/.cache/`에 둔다. CAD 평가는 `tools/cad_eval_cache.py` 하나가 파일 바이트 해시를 키로 `.cache/eval/`에 저장하므로 바뀐 CAD의 예전 평가를 읽지 않는다. 빌드는 저장·측정·매개변수 CSV·두 주문의 STL/STEP 내보내기를 CLI 한 번으로 하고(`eval` + `file.save_as`) 그 측정을 캐시에 넣어, 뒤 단계가 같은 모델을 다시 열거나 평가하지 않는다. 모델 열기가 약 20 s이고 내보내기는 수 ms다. 빌드가 내보낸 파일은 `.cache/v5/export/<모델>/`에 저장된 모델 해시와 함께 남고, `export_print_v5.py`는 그 해시가 현행 CAD와 같을 때만 쓴다. 그 밖에는 원본 CAD마다 `run` 한 번으로 두 주문을 내보내며 CLI 시간(`--timings --profile`)을 `.cache/print_v5/export-timings.json`에 남긴다. 빌드 작업 폴더는 `.cache/v5/`, 내보내기는 `.cache/print_v5/`다. 가이드 렌더와 시각 검토는 `guide/.cache/`에 남는다.

무효화는 파일 해시가 아니라 바디 형상으로 한다. 주문 기록의 각 부품에 `shape_sha256`(캐시된 BRep의 정규 JSON 해시, `cad_model.shape_digest`)이 있고, 형상·파일·벽 스캔이 기록과 같은 부품은 다시 내보내거나 스캔하지 않고 `source_sha256`만 갱신한다. 그래서 같은 형상으로 다시 빌드하거나 mount 하나를 고치면 바뀐 부품만 내보낸다(0.01 mm 변경으로 확인). 원본 CAD는 바뀐 부품이 있을 때만 연다. 가이드 렌더도 보이는 바디의 형상 지문·외관·목록 순서로 키를 잡아 바뀐 바디가 보이는 렌더만 다시 찍는다. `--clean`은 트리에 없는 파일의 평가, 옛 `guide/.cache/v5`, 렌더 id마다 가장 최근 것이 아닌 렌더, 최근 3개가 아닌 시각 검토 실행 폴더를 지운다. 빌드의 Python 준비 중 실루엣 창 래스터는 키 배치·상수·관련 함수 소스·라이브러리 버전의 해시로 `.cache/v5/prep/`에 캐시한다.

`build_seam_v5.py`는 `model/seam_v5_base.json`(plate·이음 쿠폰의 매개변수와 기능, 한 줄에 하나)에 v5 기능을 더한다. 이 파일은 2026-11-10 v4 원본에서 억제된 v4 사슬·쓰지 않는 스케치·치수를 빼고 v5 고정 변경을 넣어 만들었으며 모든 바디의 BRep이 그대로다. 같은 날 커버 3조각(`tools/cover_v5.py`)과 spine(`tools/spine_v5.py`)을 생성 코드로 옮겼다. 기반의 피처를 같은 순서·식으로 기반 타임라인 뒤에 만들며, 두 바디는 자기 피처만 건드리므로 65개 바디 BRep과 출력물이 그대로였다. 커버 분할 절삭이 돌려주는 조각 이름 순서는 타임라인 위치에 따라 바뀌므로 `cover_v5.check`가 조각별 X 범위를 확인한다. 참조 하드웨어(M2·M3 나사, 너트, 자석, 케이스 나사 62개 피처)도 같은 방법으로 `tools/hardware_v5.py`로 옮기고, 만들었다가 바로 지우던 겹침 나사 사슬 21개를 없앴다(기반 피처 164 → 81). plate는 r2 도면 스케치 수백 개 곡선에서 나오므로 기반에 남아 있다(계획 4-5). 생성기는 현행 CAD와 함께 스냅 시험편 A·C만 담은 `model/ctrl_trials_v5.sc`, 매개변수 CSV, 생성 기록을 만든다. 출력 부품은 `tools/parts_v5.py` 한 표가 정한다(주문·파일 이름·바디·원본 CAD·재료·벽 한계·출력 방향). 내보내기, 파이프라인, 정적 검사, `verify_seam_v5.py`가 이 표를 읽고, 정적 검사는 가이드 출력 부품 표의 바디·「주문 N」·STL 방향을 이 표와 대조한다. 부품을 더하거나 이름을 바꿀 때는 이 표 한 행과 CAD 바디만 고친다. 주문 1은 현행 모델의 mount·이음 쿠폰·브래킷 B, `ctrl_trials_v5.sc`의 시험편 A·C, `model/samples/46es_sw_hole_sample.sc`의 B 쿠폰·보스 탭이다. 샘플 행 C `SMP_upper`는 1.7이어야 한다. 두 주문의 내보내기는 `46es/.cache/print_v5/`에서 CAD 재평가, STL 검사와 벽 스캔을 마친 뒤 각 세트를 교체한다. 각 부품 기록에 실제 내보내기에 사용한 CAD와 STL/STEP 해시가 들어간다. 현행 CAD 해시가 바뀌면 그 모델을 사용한 두 세트를 갱신한다.

`verify_seam_v5.py`는 v5 기준 `inspection/data/seam-v5-baseline.json`(현행·시험편 CAD의 바디마다 형상 지문·부피·상자, 설계 매개변수 식)과 CSV·커버 높이·벽·간격·주문 2 출력물을 검사한다. 기준과 하나라도 다르면 실패한다. 의도한 설계 변경 뒤에는 `--accept`가 차이(추가·삭제·바뀐 바디의 부피와 상자, 매개변수)를 출력하고 기준을 다시 쓴 뒤 검증한다. 출력된 차이를 검토해 커밋 메시지에 적는다(AGENTS.md §5). 정적 검사도 커밋된 CAD의 형상 지문·매개변수를 이 기준과 대조한다. 2026-11-10까지 쓰던 v4·평판 Z 18 기준 CAD(`model/baselines/`)는 이 기준으로 바꾸고 지웠다(태그 `46es-pre-cleanup-2026-11-09`). mount 4개는 주문 1 STL의 단면(Z 1.0·2.5·3.6·6.0)을 `model/mounts_cadcraft_phase1.dxf`와 매개변수로 만든 기준 프로파일과 비교하고, 팔각 랜드 보존·육각 포켓 벽·층별 부피를 확인한다. 받침은 plate 밑면과의 접촉 면적 및 간섭을 CAD에서 검사하고, 실제 하중·공차·배선은 시험 조립에서 확인한다. 검증 결과 JSON은 다시 실행할 때 생성되는 기록이며 수동으로 통과 상태를 고치지 않는다.

`verify_assembly_reference_v5.py`는 마운트 4개를 46키의 센터·양쪽 다리·금속 단자 참고 형상과 3D 비교한다. 설계 하한은 0.4 mm다. 참고 형상에 납땜과 배선은 포함되지 않으므로 실제 간섭과 강성은 위 실물 시험에서 확인한다. 변경이 조립에 영향을 주면 [가이드 시각 검토](../guide/README.md#시각-검토)에서 해당 단계와 완성 상태까지 확인한다.

## CAD 없이 할 수 있는 검사

```sh
python -B 46es/tools/check_repository.py
python -B 46es/tools/smoke_test.py
python -B 46es/tools/finish.py      # 커밋 전: stage 범위 → 위 두 검사 → git diff --cached --check → 작성자 → 보고 틀
git config core.hooksPath .githooks # clone마다 한 번: 46es를 건드리는 커밋에 finish.py --hook(스모크·보고 틀 제외)을 건다
```

`check_repository.py`는 현행 경로·문서 링크·가이드 부품 참조·생성 기록·CAD/CSV·입출력 해시·시험/본 출력 STL의 연결성·모서리·부피·기록을 검사한다. 문서 수치도 대조한다: `model/print_v5/README.md` 부품 표의 측정 칸(크기, 주문 2 부피·최소 벽, (cm³) 메모)은 `tools/doc_tables.py`가 출력 기록·벽 검사에서 쓰고 정적 검사는 그 결과와 글자까지 같기를 요구한다(파일 목록·재료는 `parts_v5.py`와 대조). 낡았으면 `doc_tables.py --write`. `design.md` 「현행 치수」는 문장 속 수치라 생성하지 않고, 형상 기준의 매개변수 값과 적힌 자릿수까지 맞는지만 본다(대조하는 행과 식은 `DESIGN_ROWS`). 수치를 바꾸는 설계 변경 뒤 이 검사가 고칠 문서 행을 알려 준다. `smoke_test.py`는 생성기의 순수 Python 형상(mount 윤곽의 층별 부피, 브래킷 금지 영역·벽, 커버 창)을 다시 계산해 커밋된 검증 기록·주문 1 부피와 비교한다(약 15 s). 둘 다 SolidCraft의 재평가·간섭 계산이나 브라우저 조작을 대신하지 않는다. 가이드 브라우저 검사는 [가이드 안내](../guide/README.md)를 따른다.

생성기만 정리하고 형상이 그대로면 `build_seam_v5.py --refresh-record`를 쓴다. 캐시에 다시 빌드해 커밋된 CAD의 문서와 모든 바디 BRep가 같을 때만 생성 기록의 입력 지문을 갱신하고 CAD는 그대로 둔다. 다시 빌드한 CAD는 형상이 같아도 zip 바이트가 달라, 교체하면 그 해시에 묶인 주문 1·2 기록·검증·검토 모델이 모두 낡은 것이 되기 때문이다. 하나라도 다르면 실패하므로 그때는 전체 재생성을 한다.

검증 기록에는 검증 스크립트와 읽은 파일의 지문(`inputs`)이 들어간다. 검증기를 고치고 다시 실행하지 않으면 `check_repository.py`가 예전 `ok`를 낡은 것으로 막는다(AGENTS.md §6).

CI는 두 검사로 현행 경로·문서·출력물 불일치와 생성 논리 회귀를 차단한다. 추적 파일 목록과 바이트는 git이 관리하므로 별도 목록 파일을 두지 않는다(`manifest.json`은 2026-11-10 폐지).

텍스트는 `.gitattributes`로 LF를 고정한다. 정리 전 조립 메타데이터의 실측 JSON 해시는 Windows CRLF 사본의 값이었다. 원본 관찰값과 CAD는 바꾸지 않고 Git에 저장된 LF 바이트의 해시로 정규화했다.
