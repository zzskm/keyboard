# 검증과 다음 작업

현행 **v5, 주문 전(시험 출력 대기)**. CAD 검사 통과 ≠ 실물 통과.

## 변경 유형별 확인

| 변경 | 최소 확인 | 비고 |
|---|---|---|
| 문서/링크 | `python -B 46es/tools/check_repository.py` | CAD/실물 불필요 |
| 정적 검사 로직 | 위 + 관련 동작 확인 | CAD 재생성 불필요 |
| v5 형상/생성기/샘플 원본 | 현행 CAD·제작 세트 갱신 및 형상 검사. 조립 모델에 영향이 있으면 검토 CAD 갱신 후 가이드 시각 검토 | SolidCraft/NumPy/SciPy. 실물 별도 |
| 가이드 spec/3D/자산 | [시각 검토](../guide/README.md#시각-검토)로 변경 단계 확인. 화면·조작이 바뀌면 데스크톱·모바일 브라우저 검사도 수행 | Playwright 필요 |
| 출력물/주문 세트 | STL 연결성·모서리·부피/경계/방향/해시, 제작 안내 | 업체 출력 품질 별도 |
| 실물 시험 | 아래 목록 기록, 통과/수정/보류 | CAD와 별개 |

미실행은 `미실행`, 실물은 `실물 확인 대기`로 표기. 과거 `ok` JSON 재사용 금지.

## 커버 및 plate L/R 개선 계획

상태는 설계 후보 검토 전이다. 치수와 합격 기준은 1차 비교용이며, 실측과 시험 결과를 기록한 뒤 채택한다.

### 0. 기준 리비전과 현행 형상 확인

- 병합 상태가 정리된 기준 커밋을 확정한다. 생성기, CAD, 치수 CSV, 조립 검토 모델, 쿠폰을 같은 리비전으로 맞춘다. 현행·후보 쿠폰은 [생성기](../tools/build_seam_v5.py)의 공통 치수에서 생성하고, [내보낸 치수 CSV](../model/parameters_seam_v5.csv)로 대조한다.
- 앞 이음, 중앙 앞 mount, 인접 스위치, 커버를 같은 단면에 표시한다. 나사머리와 커버, 너트·나사 끝과 mount, 반턱 접촉면을 확인한다. 검토 중 언급된 빨간 띠·원은 원본 도면 또는 캡처 확보 후 해당 바디와 대조한다. 실제 간섭이 확인되면 후보 설계 전에 해결한다.
- 현행 L/R 출력품을 각각 기준 평판에 올리고, 돌출 피처를 피해 동일 높이 블록 3개로 받친다. 체결 전 이음의 앞·중앙·뒤 높이와 최대 편차를 기록해 본체 휨과 이음 형상의 영향을 구분한다.

### 1. 커버 창 단순화 및 높이 검토

1. 창 단순화는 main에 채택했다(2026-11-10, [결정 이력](design.md#결정-이력)): 키 블록 실루엣 윤곽 2개, 셀 20.35, 외곽 살 1.1, 윗면 Z 19 유지. 높이(아래 2–4)는 `codex/46es-cover-plate-trial` 브랜치에서 시험한다. 저상화하면 창 윤곽과 자석·보스 주변 잔여 두께를 같은 방식으로 다시 확인한다.
2. PSD60 지지대 상면을 기준으로 앞·뒤 테두리 높이를 잰다. r2 조립품의 같은 위치에서 돌출을 재고, 실제 키캡 스커트 높이를 쉴 때와 끝까지 눌렀을 때 각각 기록한다. r2 커버 본체는 공칭 7 mm, v5 현행은 6 mm다. v5의 약 5 mm 돌출은 CAD와 대략 실측 테두리의 차이며, r2 현물 기록은 최소 3 mm다.
3. 현행 Z19와 첫 후보 Z18.5를 비교한다. Z18.5에서 본체 5.5 mm, 테두리 위 약 4.5 mm, 참고 키캡의 정지 상태 스커트 덮임 약 1.2 mm다. 추가 저상화가 필요하면 Z18을 비교한다. 이때 각각 5.0, 약 4.0, 약 0.7 mm다.
4. 참고 키캡의 정지·4 mm 눌림 상태에서 창과의 최소 간격 1.0 mm, 다리 자석 포켓 위 살 1.3 mm 이상을 확인한다. 보스와 립의 착좌, 창 가장자리의 연속된 살, 앞 이음 나사머리 간격을 CAD에서 확인한 뒤 실제 키캡의 스트로크·풀러 접근과 커버 흡착·들뜸·휨을 시험한다. 현행과 후보의 정면·측면 단면에 돌출량을 표시한다.

### 2. plate L/R 앞 이음 및 하중 경로

1. SO3·SO6 M3 홀이 어느 plate에 속하는지 CAD에서 확인하고, R 안쪽 열 아래 직접 닿는 mount 받침을 표시한다. R에 직접 체결되는 M3가 우측의 SO4·SO5 두 개라면, 받침이 닿는 곳은 mount로 하중을 전달하고 그 사이의 하중은 R plate 굽힘을 거쳐 앞 반턱과 중앙·뒤 spine으로 분담된다. 반턱의 접촉면은 눌림을 받고 M2는 반턱을 조여 들뜸을 억제한다. Rear shim은 접촉 여부를 별도로 확인한다.
2. 앞 이음은 위에서 끼우는 직선 반턱 **2.4 mm**, 위치결정 턱 편측 **0.15 mm**, 저두 **M2×5 한 개**로 시작한다. 스위치와 잔여 벽 두께를 고려해 턱을 나사에서 가능한 멀리 두고, 턱의 접촉면으로 벌어짐과 평면 내 회전을 제한한다. 하부 spine의 M2 4개, 배선 홈, 받침은 비교 기간에 현행 구성을 사용한다.
3. R의 측면 삽입식 육각 너트 포켓은 실제 M2 너트 대변 4.0 mm·두께 1.6 mm를 출발값으로 잡는다. 육각 면으로 회전을 막고 입구 턱으로 빠짐을 제한하며, 반대쪽 구멍으로 밀어내 교체할 수 있게 한다. 너트 삽입 경로·mount 회피 공간·포켓 벽과 분말 제거를 단면에서 확인한다. 벽 두께나 유지력 기준을 충족하기 어려우면 열압입 인서트를 비교한다.
4. 현행 도브테일과 직선 반턱을 동일한 MJF 재료·출력 방향·하드웨어·체결 조건으로 시험한다. 위치결정 턱 여유는 0.15 mm와 한 단계 넓힌 값을 비교하고, 너트 포켓 여유는 독립적으로 시험한다. 본체에서는 앞 이음만 체결한 상태, spine을 붙인 상태, 케이스 장착 상태 순으로 앞·중앙·뒤 단차를 기록한다.

| 시험 | 1차 합격 기준 |
|---|---|
| 쿠폰 삽입 | 나사 없이 손으로 5회 중 5회 완전 착좌 |
| 너트 유지 | 나사를 뺀 채 뒤집어 가볍게 흔드는 10회 동안 이탈 0회, 위에서 체결할 때 공회전 0회 |
| 쿠폰 단차·내구 | 체결 후 단차 0.20 mm 이하. 10회 탈착 후 단차와 면내 유격 증가 각각 0.10 mm 이하, 포켓 균열 없음 |
| R 안쪽 열 하중 | 케이스 완전 조립 상태에서 앞·중앙·뒤의 이음에 가장 가까운 R쪽 키 위치를 각각 5 N으로 누른다. L/R 상대 변위 0.20 mm 이하, 하중 제거 후 잔류 변위 0.10 mm 이하, 현행 대비 상대 변위 증가와 반복 소음 없음 |
| 배선·정비 | 배선이 spine 홈에 눌리지 않고 상부 M3 6개를 풀어 plate·스위치·배선 모듈을 통째로 들어낼 수 있음 |

앞쪽에서 회전이나 들뜸이 남으면 턱의 접촉 방향과 나사와의 거리를 먼저 조정한다. 그래도 기준을 넘으면 M2 두 개를 검토한다. 중앙·뒤쪽에만 움직임이 남으면 spine 접촉과 Rear shim을 별도로 검토한다. 5 N은 현행과 후보를 비교하기 위한 시험 하중이다.

### 3. 채택 및 반영

첫 산출물은 기준 리비전이 표시된 현행 앞 이음 단면과 R 안쪽 하중 경로, 커버 현행·후보 단면이다. 채택 치수와 시험 결과를 기록한 뒤 생성기, 영향받는 검토·제작 출력, 쿠폰, 검증 결과와 조립 가이드를 함께 갱신한다. CAD 검사와 실물 합격은 각각 기록하고, 본 출력 여부는 시험 결과를 바탕으로 결정한다.

## 재생성 (저장소 루트)

SolidCraft CLI와 `46es/requirements.txt`의 Python 패키지(`pip install -r 46es/requirements.txt`)가 설치된 Windows 환경에서 실행한다. CLI 경로는 환경변수 `SOLIDCRAFT_CLI`, 없으면 기본 설치 경로 `C:/Program Files/SolidCraft/solidcraft-cli.exe`다(`tools/common.py`). 가이드는 `--cli`로도 지정할 수 있다. 콘솔 출력은 스크립트가 UTF-8로 바꾸므로 `PYTHONUTF8`을 따로 설정하지 않아도 된다.

```sh
python 46es/tools/build_seam_v5.py --mounts   # mount만 바꿀 때: 수 초, 도면 단면 비교
python 46es/tools/build_seam_v5.py --refresh-record   # 형상이 그대로인 생성기 정리 뒤: CAD 유지, 생성 기록만 갱신
python 46es/tools/build_seam_v5.py
python 46es/tools/export_seam_v5_review.py
python 46es/tools/export_print_v5.py
python 46es/tools/export_print_v5.py --trial
python -B 46es/inspection/scripts/verify_seam_v5.py
python 46es/tools/build_assembly_reference_v5.py
python -B 46es/inspection/scripts/verify_assembly_reference_v5.py
python 46es/guide/build_guide.py
```

`--trial`은 현행 모델의 mount·이음 쿠폰과 `model/samples/46es_sw_hole_sample.sc`의 B 쿠폰·보스 탭을 내보낸다. 샘플 행 C `SMP_upper`는 1.7이어야 한다. 두 주문의 내보내기는 `46es/.cache/print_v5/`에서 CAD 재평가, STL 검사와 벽 스캔을 마친 뒤 각 세트를 교체한다. 각 부품 기록에 실제 내보내기에 사용한 CAD와 STL/STEP 해시가 들어간다. 현행 CAD 해시가 바뀌면 그 모델을 사용한 두 세트를 갱신한다.

`verify_seam_v5.py`는 고정 기준 CAD의 해시·미변경 바디·CSV·커버 높이·벽·간격·주문 2 출력물을 검사한다. mount 4개는 주문 1 STL의 단면(Z 1.0·2.5·3.6·6.0)을 `model/mounts_cadcraft_phase1.dxf`와 매개변수로 만든 기준 프로파일과 비교하고, 팔각 랜드 보존·육각 포켓 벽·층별 부피를 확인한다. 받침은 plate 밑면과의 접촉 면적 및 간섭을 CAD에서 검사하고, 실제 하중·공차·배선은 시험 조립에서 확인한다. 검증 결과 JSON은 다시 실행할 때 생성되는 기록이며 수동으로 통과 상태를 고치지 않는다.

`verify_assembly_reference_v5.py`는 마운트 4개를 46키의 센터·양쪽 다리·금속 단자 참고 형상과 3D 비교한다. 설계 하한은 0.4 mm다. 참고 형상에 납땜과 배선은 포함되지 않으므로 실제 간섭과 강성은 위 실물 시험에서 확인한다. 변경이 조립에 영향을 주면 [가이드 시각 검토](../guide/README.md#시각-검토)에서 해당 단계와 완성 상태까지 확인한다.

## CAD 없이 할 수 있는 검사

```sh
python -B 46es/tools/check_repository.py
python -B 46es/tools/smoke_test.py
python -B 46es/tools/finish.py      # 커밋 전: stage 범위 → 위 두 검사 → git diff --cached --check → 작성자 → 보고 틀
```

`check_repository.py`는 현행 경로·문서 링크·가이드 부품 참조·생성 기록·CAD/CSV·입출력 해시·시험/본 출력 STL의 연결성·모서리·부피·기록을 검사한다. `smoke_test.py`는 생성기의 순수 Python 형상(mount 윤곽의 층별 부피, 브래킷 금지 영역·벽, 커버 창)을 다시 계산해 커밋된 검증 기록·주문 1 부피와 비교한다(약 15 s). 둘 다 SolidCraft의 재평가·간섭 계산이나 브라우저 조작을 대신하지 않는다. 가이드 브라우저 검사는 [가이드 안내](../guide/README.md)를 따른다.

생성기만 정리하고 형상이 그대로면 `build_seam_v5.py --refresh-record`를 쓴다. 캐시에 다시 빌드해 커밋된 CAD의 문서와 모든 바디 BRep가 같을 때만 생성 기록의 입력 지문을 갱신하고 CAD는 그대로 둔다. 다시 빌드한 CAD는 형상이 같아도 zip 바이트가 달라, 교체하면 그 해시에 묶인 주문 1·2 기록·검증·검토 모델이 모두 낡은 것이 되기 때문이다. 하나라도 다르면 실패하므로 그때는 전체 재생성을 한다.

CI는 두 검사로 현행 경로·문서·출력물 불일치와 생성 논리 회귀를 차단한다. 추적 파일 목록과 바이트는 git이 관리하므로 별도 목록 파일을 두지 않는다(`manifest.json`은 2026-11-10 폐지).

텍스트는 `.gitattributes`로 LF를 고정한다. 정리 전 조립 메타데이터의 실측 JSON 해시는 Windows CRLF 사본의 값이었다. 원본 관찰값과 CAD는 바꾸지 않고 Git에 저장된 LF 바이트의 해시로 정규화했다.
