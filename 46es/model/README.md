조립 화면에서 사용하는 [46es_assembly_review.sc](46es_assembly_review.sc)는 부분 실측 PSD60 케이스·MX 스위치·OEM 키캡을 반영한 **조립 검토용 파생 모델**이다. v4 출력 부품은 보존했다. [치수 근거와 재생성 방법](../docs/assembly-reference-2026-11-06.md)을 참고한다. 테두리 Z=14 / 커버 윗면 Z=15 mm로 검토 모델의 돌출량은 약 1 mm다.

### plate 보호: 맞춤은 다른 부품과 조립 단계에서 (2026-11-05)

plate는 가장 비싼 출력물이다(75.6 cm³, 스위치 홀 46개, 3층). 사용자 요청(2026-11-05): plate를 다시 출력하지 않도록, 맞지 않을 수 있는 곳은 조립에서 해결한다. 그래서 **plate 치수를 기준으로 두고, 어긋남은 상대 부품 쪽이나 조립 단계에서 흡수한다.** 교환식 블럭(볼트 구멍 주변만 따로 출력)도 검토했지만 버렸다: 자리가 없고(커버 보스 둘레 살 1.0–1.4, plate 카운터보어 ↔ 단차 안쪽 벽 0.7(SO4)–1.6), 블럭 ↔ 포켓 끼움이 하나 더 생기며, JLC 재주문은 크기와 상관없이 배송·대기가 같다.

JLC3DP FDM 치수 공차는 100 mm 이하 ±0.3, 그 이상 ±0.4%다. plate와 프레임은 따로 출력되므로 두 부품 사이 간격 차는 최악일 때 두 공차를 더한 값이다.

| plate ↔ 상대 | 어긋날 수 있는 것 | 설계 대응 | 그래도 안 맞으면 (plate는 그대로) |

**조립 순서 (위치를 맞춘 뒤 조이기)** — 처음 한 번, 그리고 프레임이나 plate를 바꿨을 때:

1. 케이스 밖에서 프레임 포켓에 스탠드오프 6개를 넣고, 프레임 아래에서 M3 나사를 손으로만 돌려 둔다(장공 쪽은 가운데쯤).
2. plate를 얹고(스위치·배선 전이어도 된다) 위 나사 6개를 조인다 → 장공 쪽 스탠드오프 4개가 plate 구멍 위치로 따라간다.
3. 프레임째 뒤집어 아래 나사 6개를 조인다. 버튼헤드 Ø5.7이 장공 폭 3.3 위에 앉는다(편측 1.2). 필요하면 M3 와셔를 쓴다.
4. 위 나사를 풀어 plate를 떼고, 프레임을 케이스에 고정(케이스 나사는 plate 아래라 이때만 닿는다)한 뒤 plate를 다시 얹고 위 나사를 조인다.

이후 정비는 위 나사만 푼다. 스탠드오프는 육각 맞변이 장공 벽에 막혀 돌지 않으므로 위 나사를 풀 때 아래 나사가 같이 풀리지 않는다.

같은 문제가 **프레임 ↔ 케이스**에도 있다. H01·H05·H06이 원형이고 H05 ↔ H06이 277.6 떨어져 있어, 프레임 외곽 오차가 최악이면 케이스 나사가 들어가지 않는다(프레임 재출력 위험, plate는 무관). 이번에는 손대지 않았다. M08 실측 때 H06(또는 H05)을 X 장공으로 바꿀지 정한다.

- **커버 고정 = 자석, 조립이 가장 쉬운 안으로 결정(사용자).** 논의: 자석만으로는 가운데 T 조각이 X로 약 ±1 미끄러지므로(립은 위·아래 변에만 있음) 면내 위치결정이 따로 필요했고, 레일 대신 **스탠드오프 6곳의 카운터보어에 꽂히는 보스**를 택했다(조각당 2점 = 위치·회전 결정, FDM 레일은 공차·마찰 문제). plate 카운터보어를 2 → `TBD_so_cb_D` 3.5로 내려 버튼헤드(1.65) 위에 1.85의 빈 공간을 만들고, 커버 보스 Ø5.6×1.5가 그 안에 들어간다. 보스 끝 Ø4.2×2.1 포켓의 Ø4×2 네오디뮴 자석이 **강철 나사머리**(0.35 아래)를 끌어당기므로 plate 쪽에는 자석도 포켓도 없고 극성·상대 자석 이탈 문제가 없다 → **스탠드오프 나사는 탄소강(흑색·아연도금) M3 버튼헤드, 스테인리스 A2 불가**(`TBD_so_screw_D` 주석). 조립 = 조각을 카운터보어 위에 올려놓기. 지렛대 홈은 지금 수치(베젤 밑면이 테두리보다 0.8~1.1 위, 커버 윗면은 2.8~3.1 위)로는 불필요, 조각마다 자석이 한쪽 끝(모서리 쪽)에 몰려 있어 반대쪽 끝을 들면 벗겨진다. ## 실측 후 재개 절차

### 1. 측정값 기록

측정 현장에서는 `measure_psd60.html`을 브라우저로 열어(오프라인 가능, 휴대폰도 됨) 칸을 채우고 **JSON 내보내기** 텍스트를 Claude Code 세션에 붙여넣는다 → 세션이 `measurements.csv`·`parameters.csv`·`.sc`에 반영한다. 손으로 할 때는 `measurements.csv`의 `실측값`·`측정일`·`메모` 칸을 채운다. 여러 곳을 잰 항목은 모든 값을 남긴다(예: `286.62 / 286.58 / 286.71`). 사진·본뜨기 파일은 `measurements/` 폴더에 측정 ID로 시작하는 이름으로 둔다(예: `M03_corner_FL.jpg`).

### 2. 매개변수 반영

`parameters.csv`에서 해당 행을 고친다.

- 값: `expression`을 실측에서 정한 설계값으로 바꾼다. 여러 값을 쟀다면 어느 값을 썼는지 주석에 적는다(최솟값, 평균 등).
- 주석: 상태 태그를 `[실측 YYYY-MM-DD Mxx]`로 바꾼다.
- 이름: 근거가 확정된 값은 `TBD_`·`CAND_`를 뗀다(예: `TBD_case_in_W` → `case_in_W`, `CAND_H01_X` → `H01_X`). 접두어가 남아 있으면 아직 미확정이라는 뜻이다.
- Wilmore 대용: 지금 `REF_WIL_…`을 참조하는 `TBD_` 행도 같은 방법으로 식을 실측값(숫자)으로 바꾼다(예: `TBD_case_in_W`의 `REF_WIL_in_W` → `286.52 mm`). `REF_WIL_` 행은 고치지 않는다.

남은 미확정 개수는 `grep -c '^TBD_\|^CAND_' parameters.csv`로 확인한다.

### 3. SolidCraft 갱신

1. `46es_draft_sketches.sc`를 SolidCraft에서 연다. MCP로 열 때는 서버가 허용한 폴더만 읽을 수 있다. 서버에 `--allow-path D:\work\keyboard\46es\model`을 추가하거나, 파일을 SolidCraft recovery·temp 폴더로 복사해 연다.
2. 바뀐 값은 `parameters.change`로 반영한다. 이름을 바꿀 때는 `new_name`을 쓰면 스케치 참조가 따라간다. 여러 개를 바꿀 때는 `batch` + `coalesce_parameters: true`를 쓴다.
3. 확인: 스케치 12개 모두 `dof 0`, 타임라인 오류 0. `TBD_pcb0_dx/dy`가 바뀌면 고정 숫자 DXF 4종을 다시 만들어 스케치를 교체한다(삭제 → `sketch.create` + `sketch.insert_dxf` + 전체 `sketch.constraint.fix` → 컷 재생성): `python -I ../tools/make_key_dxf.py sq 14 <dx> <dy> REF_r2_keys_sq14_gh60.dxf`(SK22), `… sq 16.5 … REF_r2_keys_sq16p5_gh60.dxf`(SK24·SK25 공용), `python -I ../tools/make_r2_cover_dxf.py REF_r2_cover_windows_P4_gh60.dxf <dx> <dy>`(SK34). `jigs/`의 같은 이름 매개변수도 함께 바꾼다. 외곽은 `sketch.export_dxf`로 내보내 기대 좌표와 비교한다(검사 때 쓴 방식). 하우징 대용 바디는 부피와 `body_topology {"faces":"cylinders"}`의 기둥 중심으로 확인한다.
4. 저장한 뒤 `parameters.csv`와 `.sc`의 값이 같은지 대조하고 함께 커밋한다.
